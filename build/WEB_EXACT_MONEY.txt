v1.0.1 网页金额计算说明
英文版：WEB_EXACT_MONEY.en.txt

运行时

web/money.js 用 BigInt 系数和小数位数表示十进制数。通过 Decimal.valueOf 隐式转换会抛出异常。金额按 ROUND_HALF_UP 舍入到两位小数，单价保留六位。原始金额的绝对值上限为 999999999999.99，单价为 999999999999.999999。累计余额和报表合计可以超过单笔限额。

业务脚本

app、pro、v8、v28、sep04/05/07、oct29、inventory-workspace 和 inventory-fifo 使用 Exact 的十进制运算、比较、真假判断、排序及格式化函数。字符串、日期和 DOM 计数沿用 JavaScript 原有语义。图表只在计算平方根、绘制坐标或调用要求 Number 的接口时显式使用 toNumber 转换。

新录入的金额在入账前转为两位小数的字符串。有原始收入渠道或非空采购明细的合计可以超过单笔限额，缺少来源明细的手填合计仍受限。客人数和数量保留原有数值接口。

构建与测试

业务 JavaScript 源码位于 build/web-exact-source/。共享运行时 web/money.js 和样式表直接在 web/ 中维护。构建工具读取该运行时，重新生成业务脚本。在仓库根目录运行：

    npm ci --prefix build/js-transform && node build/compile_exact_web.cjs
    node build/test_exact_web.cjs

build/js-transform/package-lock.json 将 acorn 锁定为 8.15.0。部署后的网页无需安装 acorn 或 Node.js，也无需从 CDN 加载十进制运算库。

先进先出成本与单价显示

入库时已填写单价的，始终显示原单价。只有缺少原单价时，才用总金额除以数量推算六位小数的单价。每个批次保留原数量和原总成本。每次出库分摊的成本等于舍入后的累计应分摊成本减去此前已分摊的金额。整批出清后，累计分摊金额等于原总成本。

三件商品共 10.00 元，逐件出库时的成本依次为 3.33、3.34、3.33 元。三件商品以 0.335000 元的单价入库，总成本为 1.01 元，逐件出库依次分摊 0.34、0.33、0.34 元，显示的入库单价仍为 0.335000。同一张出库单有多行相同物料时，预览会计入前面各行已占用的数量。

保存记录

normalizePayload 只处理已知财务字段。extension 和 supplier_metadata 等未知对象保留原类型与值，即使其中的键名为 price 或 amount。保存无关字段时，已有 JSON 或纯文本格式的采购明细字符串保持原样。新增金额先由浏览器校验，再由 API 复核。品名更正在后端的同一笔事务中执行，成功后网页返回库存总览并搜索更正后的名称。

手机和平板录入

从默认的只读模式切换到修改模式时，网页会重新检查新客人数和总客人数两个字段的权限。账号有权修改且仍在服务端规定的更正时限内时，才可编辑这些字段。
